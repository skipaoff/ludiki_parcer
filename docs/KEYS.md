# Ключи бирж: как получить и куда вставить

Инструкция для владельца терминала. Одна страница на все девять торгуемых бирж.

Проверено по справкам бирж 25.09.2026. Если на бирже что-то переехало — правится этот файл, а не память.

---

## Что нужно терминалу

| Биржа | Что вводим | Поля в терминале |
|---|---|---|
| Binance | API key + Secret | 2 |
| MEXC | API key + Secret | 2 |
| Gate | API key + Secret | 2 |
| Bybit | API key + Secret | 2 |
| BingX | API key + Secret | 2 |
| Bitget | API key + Secret + Passphrase | 3 |
| KuCoin | API key + Secret + Passphrase | 3 |
| Aster | Адрес основного кошелька + приватный ключ API-кошелька | 2 |
| Hyperliquid | Адрес основного кошелька + приватный ключ API-кошелька | 2 |

Variational в списке нет: у площадки нет торгового API, её вилки видны, но взять их нельзя.

## Правила, общие для всех бирж

1. **Вывод средств — никогда.** Там, где биржа сообщает права ключа, терминал сам откажется его принять. MEXC и Gate прав не сообщают — там за этим следите только вы.
2. **Только фьючерсы и чтение.** Спот, маржа, конвертация, переводы между счетами терминалу не нужны — не включайте.
3. **Режим позиций — односторонний (one-way).** Хедж-режим терминал не поддерживает и заблокирует торговлю по такой бирже. Это настройка аккаунта, а не ключа: переключается на самой бирже до создания ключа.
4. **Деньги должны лежать на фьючерсном счёте.** В классических режимах спотовый и фьючерсный кошельки разделены; терминал видит только фьючерсный. В единых аккаунтах (Bybit, Bitget UTA, KuCoin Unified) перевод не нужен.
5. **Привязка к IP.** На Binance без неё торговый ключ вообще не выдаётся, на KuCoin торговые права отключаются через месяц простоя, на MEXC, Gate и Bybit ключ живёт 90 дней. Если внешний IP меняется, это придётся обслуживать: таблица сроков — ниже.
6. **KYC.** На централизованных биржах верификация обязательна: у MEXC — именно для фьючерсного API, у Bitget и KuCoin — для торговли вообще, у Binance нужна пройденная верификация и депозит. У Aster и Hyperliquid вход по кошельку, верификации нет.
7. **Ключ вводится один раз.** Он уходит в хранилище ключей системы (Диспетчер учётных данных на Windows, связка ключей на macOS), обратно в интерфейс не возвращается и в логи не попадает.

## Порядок подключения одной биржи

1. Создать ключ по разделу этой инструкции.
2. Настройки → Биржи → карточка биржи → вставить ключ → **[СОХРАНИТЬ И ПРОВЕРИТЬ]**.
3. Терминал сам покажет: баланс, права ключа, режим позиций, комиссии аккаунта, пинг и расхождение часов. Красное — блокирует торговлю, серое — предупреждение.
4. Пробная сделка: открывает и сразу закрывает минимальную позицию, ответы биржи сохраняет в `ludik-data/trials`.

   ```bash
   .venv/bin/python scripts/trial_trade.py <биржа> --i-understand
   ```

   ```bat
   .venv\Scripts\python.exe scripts\trial_trade.py <биржа> --i-understand
   ```

   У Binance есть демо-контур: `--demo` и отдельные демо-ключи.
5. Что вернула биржа — перенести в `docs/EXCHANGES.md` с пометкой `[проверено]`: единицы количества, комиссии, свой id ордера, reduce-only.

Торговля включается только после этого: `[trading] enabled = true` в `config.toml` и перезапуск.

## Что терминал проверяет сам, а где ошибиться нельзя

Права ключа биржи отдают по-разному. Там, где биржа их не говорит, проверить за вас некому.

| Биржа | Терминал видит право на вывод | Терминал видит привязку к IP | Режим позиций |
|---|---|---|---|
| Binance | да, ключ с выводом не примет | да | читает |
| Bybit | да | да | читает |
| Bitget | да | да | читает |
| KuCoin | да | да | читает |
| BingX | да | да | читает |
| MEXC | **нет**, биржа не отдаёт права фьючерсного ключа | нет | читает |
| Gate | **нет** | да | читает |
| Aster | ключ основного кошелька не примет | — | читает |
| Hyperliquid | API-кошелёк выводить не может по устройству площадки | — | односторонний всегда |

**Отсюда правило:** на MEXC и Gate внимательнее обычного — снимите галочки вывода руками, терминал об этом не предупредит, а только покажет «права неизвестны».

## Формат полей

- **API key / Secret:** от 8 до 256 печатных символов без пробелов. Лишние пробелы по краям терминал срежет сам.
- **Passphrase (Bitget, KuCoin):** та строка, которую вы придумали при создании ключа. Восстановить её нельзя — только пересоздать ключ.
- **Кошелёк (Aster, Hyperliquid):** адрес вида `0x` и 40 шестнадцатеричных символов.
- **Приватный ключ API-кошелька:** 64 шестнадцатеричных символа, с `0x` или без.

## Сроки жизни ключей

Ключ может тихо перестать работать. Терминал это заметит (проверка ключа начнёт отвечать отказом), но лучше знать заранее.

| Биржа | Что происходит со временем |
|---|---|
| Binance | торговый ключ вообще не выдаётся без привязки к IP; при смене внешнего IP перепривязать |
| MEXC | без привязки к IP — **90 дней**, продление за 5 дней до конца на странице ключей |
| Gate | без привязки к IP — **90 дней** |
| BingX | ключ с правом торговли без привязки к IP удаляется после **14 дней** без запросов |
| Aster | срок агента вы задаёте сами при создании |
| Hyperliquid | срок агента максимум **180 дней**, задавайте явно |
| Bybit | без привязки к IP — **90 дней**; продлевается пересохранением настройки IP. Срок появляется и после смены пароля аккаунта |
| Bitget | срок в правилах биржи не описан |
| KuCoin | торговые права без привязки к IP отключаются после **30 дней простоя**, чтение продолжает работать |

## Чем биржи отличаются после подключения ключа

У Binance и MEXC терминал держит приватный поток: биржа сама присылает, что ордер исполнен, — подтверждение приходит мгновенно. У остальных семи такого потока пока нет, и терминал спрашивает статус ордера сам: раз в секунду, до десяти раз (`[trading] status_query_attempts`), а позиции опрашивает раз в пять секунд.

На что это влияет:

- **Обычная сделка.** Разницы почти нет: ордер по рынку исполняется сразу, статус приходит первым же запросом.
- **Сбой ноги.** Если ответ биржи потерялся, на Binance и MEXC терминал узнает исход сразу, а на остальных — в течение секунды-двух. Всё это время пара висит в состоянии «открывается», и по этой монете ничего нельзя делать.
- **Ничего не теряется.** Количества для закрытия всегда берутся из реальных позиций на бирже, а не из записей терминала.

Приватные потоки для остальных семи бирж — в списке доработок (`docs/PLAN.md`, раздел 14).

## Binance

**Сначала — фьючерсный счёт, потом ключ.** Binance пишет прямо: если ключ создан раньше, чем открыт фьючерсный аккаунт, право на фьючерсы к нему уже не добавить. При включённом Portfolio Margin право на фьючерсы недоступно вообще.

1. Открыть фьючерсный счёт: Derivatives → USDⓈ-M Futures, пройти квиз.
2. Профиль → **Account** → **API Management** → **Create API** ([прямая ссылка](https://www.binance.com/en/my/settings/api-management)).
3. Включить: **Enable Reading** (стоит по умолчанию) и **Enable Futures**.
4. Не включать: **Enable Withdrawals**, Enable Spot & Margin Trading, переводы между счетами.
5. **Привязать IP.** Это не совет, а требование биржи: у обычного HMAC-ключа без привязки к IP остаётся только чтение, торговля не включится. Если внешний IP меняется, придётся перепривязывать.

До создания ключа нужны 2FA, пройденная верификация и хотя бы один депозит на спотовый кошелёк.

**Демо.** У Binance есть демо-контур: в `config.toml` ставится `[exchanges.binance] demo = true`, и в карточку вводятся отдельные демо-ключи. Первую пробную сделку делаем там.

## MEXC

**Нужен KYC** — без верификации фьючерсный API не выдадут.

1. [mexc.com/user/openapi](https://www.mexc.com/user/openapi) → создать ключ.
2. Включить права на фьючерсы: чтение и торговля (в документации это `CONTRACT_ACCOUNT_READ/WRITE` и `CONTRACT_DEAL_READ/WRITE`).
3. Не включать вывод и переводы (`SPOT_WITHDRAW_*`, `SPOT_TRANSFER_*`).
4. Привязка к IP необязательна, но **ключ без неё живёт 90 дней** и отключится сам. Продлить можно за 5 дней до истечения на странице ключей.

**Комиссии MEXC для API-торговли считаются отдельно от сайта и приложения и уже дважды росли:** 0,05% тейкер на запуске, 0,06% с 1 мая, **0,08% с 1 июня 2026**. Терминал считает ленту по 0,08%, пока биржа не сообщит ставку вашего аккаунта после проверки ключа.

**Осторожно:** MEXC не отдаёт права фьючерсного ключа, поэтому терминал не сможет предупредить о включённом выводе — проверяйте галочки сами.

## Gate

1. Профиль → **API Management**, создать ключ **APIv4** (ключи APIv2 работают только со спотом и для терминала бесполезны).
2. Права выставляются построчно: строке фьючерсов дать **Read and Write**, остальным — Read Only или ничего.
3. Кошельку право записи не давать: у Gate ключ в принципе умеет выводить средства, ограничение только в правах.
4. Привязка к IP необязательна, но **без неё ключ действует 90 дней** и принимает запросы с любого адреса.

До создания ключа нужны верификация, установленный fund password и 2FA; при создании Gate спросит fund password и код 2FA.

**Если счёт переведён в Unified Account:** при создании ключа явно выбирается тип аккаунта, а влияние объединённого счёта на уже выданные ключи в справке Gate не описано. Если после подключения терминал не видит позиции — пересоздайте ключ, выбрав тип, соответствующий вашему счёту.

## BingX

1. Профиль → **API Management** ([bingx.com/en/accounts/api](https://bingx.com/en/accounts/api)) → создать ключ.
2. Новый ключ по умолчанию **только на чтение** — право на торговлю бессрочными фьючерсами включается отдельно.
3. Не включать: вывод, Universal Transfer, управление субаккаунтами.
4. **Ключ с правом торговли и без привязки к IP удаляется после 14 дней без запросов.** Ключ с привязкой к IP бессрочный; на один ключ можно указать до 20 адресов.

Секрет показывается один раз. Ключей на аккаунт — до 20.

## Aster

У Aster два поколения API. Терминал работает по актуальному: **подпись API-кошельком**, а не парой «ключ и секрет». Создание старых ключей V1 биржа прекратила 25 марта 2026.

1. [asterdex.com/en/api-wallet](https://www.asterdex.com/en/api-wallet) → вверху переключиться на вкладку **Pro API**.
2. Создать API-кошелёк (агента). Основной кошелёк подпишет его авторизацию один раз — это нормально и происходит в интерфейсе биржи.
3. Права агента задаются галочками при создании: **торговля перпетуалами — включить**, **вывод — не включать**. Если включить вывод, биржа потребует список IP.
4. Срок жизни агента вы задаёте сами при создании — поставьте осознанный срок и запишите дату.
5. В терминал вводятся: **адрес основного кошелька** (0x…, тот, которым вы входите на Aster) и **приватный ключ API-кошелька**.

**Приватный ключ основного кошелька вводить нельзя никогда** — им подписывается только авторизация агента, и он даёт полный доступ к средствам. Терминал такой ключ не примет.

**С 1 сентября 2026** приватные запросы работают только после того, как основной кошелёк сделал депозит: иначе биржа отвечает «This function can only be used after deposit». Спотовый и фьючерсный балансы разделены — деньги нужно перевести на фьючерсный.

## Hyperliquid

Здесь тоже API-кошелёк (агент), а не ключ с секретом.

1. [app.hyperliquid.xyz/API](https://app.hyperliquid.xyz/API) → создать и авторизовать API-кошелёк.
2. **Задайте срок действия явно** — максимум 180 дней. Значение по умолчанию площадка не документирует, а истекает агент молча.
3. В терминал вводятся: **адрес основного кошелька** и **приватный ключ API-кошелька**. Адрес агента в поле кошелька вводить бесполезно — по нему счёт не найдётся.
4. Приватный ключ основного кошелька не вводить: агент умеет торговать за ваш счёт, но не умеет выводить средства — в этом весь смысл разделения.

Особенности площадки:
- счёт в **USDC**, минимальный депозит через мост — **5 USDC**: меньше отправлять нельзя, деньги потеряются;
- привязки к IP нет вообще, ограничения считаются по адресу и по частоте запросов;
- агентов на аккаунт немного (порядка трёх-четырёх плюс по два на субаккаунт) — не плодите их без нужды;
- агент исчезает, если истёк срок, если его вытеснил новый агент с тем же именем или если на счёте не осталось средств;
- перевод между спотовым и фьючерсным балансом нужен только в «ручном» режиме счёта; в объединённом режиме баланс общий.

## Bybit

Ключ создаётся **только на сайте**, в приложении такой страницы нет. Для нового аккаунта создание ключей может быть закрыто первые двое суток.

1. [bybit.com/app/user/api-management](https://www.bybit.com/app/user/api-management) → **Create New Key**.
2. Назначение ключа: **API Transaction** (не «Connect to Third-Party Applications»).
3. Права: переключить с **Read-Only** на **Read-Write** — по умолчанию стоит только чтение.
4. В таблице Trade, группа **Unified Trading**, тип **Contract**: включить **Orders** и **Positions**. Это и есть право на USDT-перпетуалы.
5. Не включать в группе Assets: **Withdrawal**, **Account Transfer**, **Subaccount Transfer**.
6. Привязка к IP необязательна, но **ключ без неё действует 90 дней**. Продлевается без пересоздания: в настройках ключа заново выбрать «No IP restriction» и сохранить — срок снова станет 90 дней, ключ и секрет не изменятся.

Парольной фразы у Bybit нет — только ключ и секрет. Классический счёт биржа упразднила, всё торгуется в едином аккаунте, поэтому отдельно переводить деньги на фьючерсный счёт не нужно. Режим маржи — настройка аккаунта, терминал его не трогает.

Отдельно: срок жизни ключу даёт не только отсутствие IP, но и смена пароля аккаунта.

## Bitget

1. [bitget.com/account/newapi](https://www.bitget.com/account/newapi) → **Create New API**.
2. Придумать **passphrase** — её же вводить в терминал. Восстановить нельзя, только пересоздать ключ.
3. Права:
   - единый аккаунт (UTA): **Unified account trade, read and write**;
   - если терминал должен менять плечо или режим позиций — дополнительно **Unified account management, read and write**;
   - классический аккаунт: **Trade**.
4. Не включать: **Withdraw** и **Transfer**.
5. Привязка к IP необязательна, биржа её рекомендует; больше 10 адресов на ключ не советует. Срока жизни ключа в правилах Bitget не описано.

**Важно сейчас:** с 15 сентября 2026 Bitget переводит классические счета в единый торговый аккаунт. Если ваш счёт мигрирует, проверьте права ключа после перевода — названия прав в двух режимах разные. В классическом режиме деньги нужно отдельно перевести на фьючерсный счёт, в едином — нет.

## KuCoin

1. [kucoin.com/account/api](https://www.kucoin.com/account/api) → **Create API**.
2. Придумать **passphrase** — её же вводить в терминал, восстановить нельзя.
3. Права: **General** и **Futures**. Если счёт переведён в единый режим — ещё и **Unified**.
4. Не включать: **Withdrawal**, **FlexTransfers**, **LeadtradeFutures**.
5. **Привязать IP.** У KuCoin это важнее, чем у других: ключ с торговыми правами без привязки к IP удаляется или теряет право торговать после 30 дней простоя. При этом права General продолжают работать — терминал будет спокойно показывать данные и падать только на ордерах.

В классическом режиме деньги нужно перевести на фьючерсный счёт отдельно. Ключ должен быть текущей версии: терминал подписывает запросы по второй версии, ключи самой первой версии подписываются иначе и не подойдут.
